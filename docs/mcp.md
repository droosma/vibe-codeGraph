# How to Use `codegraph mcp`

`codegraph mcp` starts a **Model Context Protocol (MCP) stdio server** that exposes CodeGraph as a set of native tools for AI coding agents. Once running, agents can call `codegraph_query`, `codegraph_explain`, and other tools directly — without shell commands or prompt engineering.

In practice, you rarely run `codegraph mcp` yourself. Agents launch it automatically on demand via their MCP configuration files (generated by `codegraph init`).

---

## Quick Start

```bash
# Initialize config and MCP registration files
codegraph init
# → Creates .vscode/mcp.json, .mcp.json, apm.yml

# Index your codebase
codegraph index --solution MyApp.sln

# Agents will now auto-start the MCP server when they connect.
# You can also test the server manually:
codegraph mcp
```

---

## CLI Reference

```
codegraph mcp [options]
```

| Flag | Description | Default |
|------|-------------|---------|
| `--graph-dir <dir>` | Directory containing the indexed graph | `.codegraph` |
| `--help`, `-h` | Show help | |

## Exposed MCP Tools

The server exposes eight tools. Agents call them like any other tool:

| MCP Tool | Description |
|----------|-------------|
| `codegraph_query` | Query the graph by symbol pattern with depth, edge-type, and format options |
| `codegraph_list` | Browse the graph hierarchy — assemblies, types, interfaces, namespaces |
| `codegraph_summary` | Generate an overview report: hub types, assembly boundaries, test coverage |
| `codegraph_path` | Find the shortest dependency path between two symbols |
| `codegraph_impact` | Reverse-dependency analysis — assess the blast radius of a change |
| `codegraph_explain` | Full symbol deep-dive: signature, members, all edges, test coverage |
| `codegraph_file` | Find all symbols defined in a source file by file path |
| `codegraph_batch` | Query multiple symbols in one call and receive combined results |

These tools wrap the same library code used by the CLI commands — there is no difference in capability.

## Agent Configuration

### Automatic (recommended)

Run `codegraph init` once. It detects your agent environment and writes the appropriate config files:

```bash
codegraph init
```

Generated files:

| File | Agent |
|------|-------|
| `.vscode/mcp.json` | VS Code Copilot, Cursor |
| `.mcp.json` | Claude Code |
| `apm.yml` | APM (Agent Package Manager) |

### Manual Configuration

If you need to add the server by hand, use the following snippets:

**VS Code Copilot / Cursor** (`.vscode/mcp.json`):

```json
{
  "servers": {
    "codegraph": {
      "type": "stdio",
      "command": "dotnet",
      "args": ["codegraph", "mcp"],
      "cwd": "${workspaceFolder}"
    }
  }
}
```

**Claude Code** (`.mcp.json`):

```json
{
  "mcpServers": {
    "codegraph": {
      "command": "dotnet",
      "args": ["codegraph", "mcp"]
    }
  }
}
```

**APM** (`apm.yml`):

```yaml
servers:
  codegraph:
    command: dotnet
    args: [codegraph, mcp]
```

## How the Server Works

- **Transport**: NDJSON over stdio (one JSON-RPC object per line). Compatible with VS Code Copilot and Claude Code.
- **Lifecycle**: The server starts when the agent connects and exits when the agent disconnects. It is stateless between sessions.
- **Graph loading**: On startup, `codegraph mcp` loads the graph from `--graph-dir`. The graph must have been indexed first (`codegraph index`).
- **Multi-solution**: In a [multi-solution setup](configuration.md#multi-solution-configuration), the server loads all sub-graphs and serves queries across them. Use the `from` parameter in `codegraph_query` to filter by solution.

## Troubleshooting

### Agent does not see the `codegraph_query` tool

1. Run `codegraph init` to regenerate the MCP config files.
2. Restart your agent / IDE.
3. Verify the graph has been indexed: `ls .codegraph/graph.db` (or `ls .codegraph/meta.json`).

### Server exits immediately

The MCP server reads from stdin. If stdin is closed (e.g. when running in a terminal without a connected agent), the server will exit. This is expected behavior.

### Wrong graph directory

If the server loads from the wrong directory, pass `--graph-dir` explicitly in the MCP config:

```json
{
  "servers": {
    "codegraph": {
      "type": "stdio",
      "command": "dotnet",
      "args": ["codegraph", "mcp", "--graph-dir", "/path/to/.codegraph"],
      "cwd": "${workspaceFolder}"
    }
  }
}
```
